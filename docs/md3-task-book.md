## 一、为什么需要这份清单

上一轮修的是「**明显坏掉**」的东西（占位、裁切、点了没反应、两套详情页）。但 MD3 这套界面是 6000 行新代码，很多问题是**跨页面、跨主题**的，靠一次改动不可能查完。这份任务书把已知问题和需要系统排查的点固定下来，按优先级逐条推进，每条都写清楚**验收标准**，避免"看起来对了"就收工。

排查原则：

1. **同一控件要在 4 种状态下看**：浅色 / 深色 / AMOLED 纯黑 / 跟随封面取色（换 3 首封面差异大的歌）。
2. **同一页面要在 3 种字号下看**：85% / 100% / 125%。
3. **每个可点元素至少验证**：视觉反馈、点击结果、返回后的状态。
4. 不要只依赖截图：截图是 1080×2354，用工具看时会被缩到约 500 宽，**坐标要 ×2.16 才是真实像素**。

## 二、本轮已验收（v2.1.1，7 项）

| # | 问题 | 根因 | 现状 | 复验方式 |
|---|---|---|---|---|
| 1 | 大卡片文字被圆角裁切 | 把「封面 + 文字」整块 `clip` 到 16dp 圆角，底部文字两端落在弧线上 | 只裁封面，文字在裁剪之外，底部留白 8dp | 首页「为你推荐」卡片，三种字号下看文字左右两端 |
| 2 | 迷你条与底栏分离、下方不显示页面 | 迷你条和导航栏一起放在 `bottomBar` 的 Column 里，等于把内容整体顶上去 | 迷你条改为**悬浮胶囊**（`align(BottomCenter)` 在内容之上）；`bottomBar` 只留导航栏；列表用 `LocalMd3MiniInset` 留 84dp | 播放中回首页：胶囊下方/两侧应看到列表内容；滚到底最后一条不被盖 |
| 3 | 迷你进度条不符合规范 | wavy 进度被压到 2dp：波形是 Expressive 表达，需 ≥4dp 厚度 + 振幅空间 | 标准线性指示器：4dp、圆角端帽、轨道 16%、水平内边距 16dp（> 圆角半径） | 放大截胶囊底部：线在内部、两端不被切 |
| 4 | 两套详情页 | 迷你条 → 全屏播放页；歌曲列表 → 歌曲详情 | 删除播放页与 `Md3Dest.Player`；迷你条 → 歌曲详情；详情页合并传输控件 | 点迷你条与点歌曲行应到**同一页**；全局搜 `Player` 无残留 |
| 5 | 发现页缺头像与搜索 | 只有首页/资料库有 | 补搜索 + 头像，抽出共享 `Md3AvatarButton` | 首页 / 发现 / 资料库 三个 tab 右上角一致 |
| 6 | 状态栏颜色与可视性 | 只设了 `setDecorFitsSystemWindows(false)`，**从未设 `isAppearanceLightStatusBars`** | `Md3Theme` 里按**实际主题**（非系统深色状态）设图标明暗；tab 页加状态栏遮罩，详情页封面顶部加 22% scrim | 强制「常暗」→ 图标白；强制「常亮」→ 图标黑；列表滚到顶/中/底各看一次 |
| 7 | 搜索页标题缩进 | `Md3PageHeader` 自带 16dp，外面又包了 16dp | 去掉外层 | 四个 tab 的标题左边缘应完全对齐（可用截图取像素比较） |

## 三、待办清单

> 优先级：**P0** 功能/正确性（会让人用不了）＞ **P1** 视觉与布局 ＞ **P2** 交互与动效 ＞ **P3** 适配与无障碍 ＞ **P4** 工程质量。

### P0 · 功能与正确性（10 条）

| # | 目标 | 现状 / 线索 | 涉及文件 | 验收标准 |
|---|---|---|---|---|
| P0-1 | 平板 / 横屏 / 折叠屏可用 | 只有 `≥720dp → NavigationRail` 逻辑，从未真机验证；内容宽度无上限，横屏会拉成一条 | `Md3App.kt`、各 `Md3*Screen` | 横屏：内容最大宽度 ≤ 840dp 并居中；Rail 与内容不重叠；折叠屏展开/收起不崩 |
| P0-2 | 返回栈行为一致 | 根页返回已改为回「首页」；但设置二级页返回、详情多级跳转（歌单→歌曲→艺人）易错 | `Md3App.kt`、`Md3Settings.kt` | 任意 3 级跳转后连按返回，逐级退回且不丢滚动位置 |

| P0-5 | 搜索缺历史与分页 | 只有热门词与最近播放；结果无分页 | `Md3Screens.kt`、`Md3Config.kt` | 搜索历史持久化（最多 10 条，可单条删除/清空）；结果滚到底加载下一页 |

## 四、每轮必做的验收流程

改完任何一处，按这个顺序过一遍（约 6 分钟）：

```
1. 构建安装
   ./gradlew :androidApp:assembleRelease --offline
   adb install -r androidApp/build/outputs/apk/release/androidApp-release.apk
2. 冷启动 → 首页（顶部无占位、状态栏图标可读）
3. 首页滚动到底（迷你胶囊悬浮、最后一条不被盖）
4. 点歌曲行 → 详情（头部渐变无断层、传输行居中、次操作无裁切）
5. 详情滚动（折叠顶栏出现、返回键消失）
6. 返回 → 发现（右上角头像/搜索）
7. 资料库 → 歌单（封面/标题/数量/两个按钮）
8. 统计（卡片有层次、柱状图正常）
9. 搜索（标题与其它页对齐、输入有清除、结果可点）
10. 设置 → 外观（改配色/圆角/字号，立即生效不用重启）
11. 设置 → 播放 / 音源 / 存储（无失效项、有确认弹窗）
12. 强制「常亮」再走一遍 2–9（浅色主题）
```

辅助命令：

```bash
# 取坐标（真实像素）
adb shell uiautomator dump /sdcard/ui.xml
adb pull /sdcard/ui.xml ./ui.xml   # 注意 MSYS 会改写路径，前面加 MSYS2_ARG_CONV_EXCL="*"

# 只抓崩溃
adb logcat -d | grep -E "FATAL EXCEPTION" -A 20

# 掉帧
adb shell dumpsys gfxinfo com.asmusic.app framestats
```

## 五、明确不做 / 暂不做

- **不做**：MD3 专属的分享海报编辑器（沿用经典界面的实现）。
- **不做**：动态取色接系统壁纸（Monet）—— 需要 Android 12+ 系统 API，且与「跟随封面」冲突，留作选项以后再说。
- **暂不做**：平板双栏（列表 + 详情并排）。等 P0-1 验证完再决定。
- **暂不做**：歌词逐字动画的性能优化，先保证正确性。

## 六、版本与发布约定

- 修 bug：`2.1.x`（versionCode +1）；加功能：`2.2.0`。
- 每次发版必须同时：升 `versionName` / `versionCode`、更新 README 的 MD3 章节、在 Release 说明里列出「改了什么 / 为什么 / 怎么验」。
- **发版前必须跑完第四节 12 步**，并在 Release 说明里写明本次验证覆盖了哪几步、跳过了哪几步（跳过要写原因）。
